## 本轮已复现并修复

1. **泛化 HVAC 资料能被误当作任意 H01–H09**：修复前 9 个画像缺少独立能力证据仍 qualified，另一个 commercial-only 样本被接受为 residential H01。现按 `config/hvac-qc-on.json` 的 `profile_qualification` 核验；缺失/未审进入 Review，已审明确不符进入 Excluded。新增字段不会从关键词或模型猜测生成。
2. **未知采购权仍能 Fit 80 且 qualified**：None、0、False 三种输入均已复现。企业画像现在必须有已核实的正向采购决策权证据，Fit 不替代此人工核验门槛。
3. **负面资质证据能支持 verified**：修复前 HTTP 200；现拒绝。真实资质证据的值须明确对应 `status/province/work_class/authority`（not_required 不要求 authority 字段匹配，但仍需原有官方来源核验），不能用裸 true 推断施工类别或免责。DEMO 的 true 仅兼容明确标记的模拟数据。评估阶段也复查，旧记录不能绕过。
4. **证据到期，列表仍显示已合格**：修复前 dashboard 的 Account/Lead 状态与实时漏斗矛盾。列表现在返回当前证据/策略重新评估的状态和分数，保留持久记录标识，GET 不修改审计或数据库评分记录。
5. **手机画像卡片撑破屏幕**：新浏览器复验中 390px 视口出现 410px 文档宽度。修复 grid track 的自动最小宽度与卡片 min-width，保留横向导航在其自身滚动容器内，不通过裁切页面隐藏溢出。

修复前分别运行回归测试，观察 **12 + 3 个失败用例**；修复后包含边界扩展共 25 个新增用例通过。全套后端从 60 扩展至 85，通过且无跳过；浏览器还增加了手机 ICP 条件展示与溢出检查。DEMO 数据通过正常研究任务刷新，没有重置退订或把模拟客户变成真实客户。

修复后的 [手机画像页面](previews/workspace-icp-mobile.png)已视觉核对，390px 浏览器溢出断言通过。

## 六项复验需要的资料与步骤

1. 业务负责人确定 NEXA 真实产品/合作范围和各画像判定依据；合规负责人确认来源用途、资质工作类别与联系依据。不能用未知参数或假定法规补齐。
2. 参考模板 JSON 与 API 官方政策补审，通过环境设置安全绑定凭据并启用有期限/额度的 SourcePolicy。当前网络草稿尚未应用，不能绕过运行时代理。
3. QC/ON 各两城合计 50 家真实公开经营主体，保留 URL、观察时间、原文、许可、独立人工核验与人工画像标签；包含合格、错配、H10、无资质资料、停止经营等负例。类别不足或 Unknown 的样本单独报告，不能强行补齐。
4. 对比系统结果和独立标签，报告画像 precision、核验率、错误合格、Unknown 覆盖与原因；AI 每项声明是否受来源支持、Intent 日期和人工评分差异。PRD 的 Verified/Qualified 比率是试点假设，不自动当成承诺的精准率阈值。
5. 用人工批准的 FR/EN 草稿、真实入站回复或明确隔离的测试回复验审批/分类/CRM。保持无自动发送；送达/回复转化指标无实际基础时为 null。
6. 用户/验收负责人按给定六项权重记录得分与证据。未提供细项规则时只出证据/缺口，不自造子项分值或宣称 100 分。

只读刷新证据报告：`.venv/bin/python scripts/acceptance_report.py`。它读取真实工作租户与测试结果，不创建客户、不联系客户、不调用付费模型，也不自动提高用户给定的分数。
